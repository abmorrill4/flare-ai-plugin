# House Style 0.2.0

This release answers the feedback from the first pilot. It adds a first-run setup, a rule-by-rule view of Check project,
a browser for every style rule, owner approval for changes to a team's guide, and automatic updates.

## Install or upgrade

1. Download `HouseStyle-0.2.0.zip` and extract all of it.
2. Close Flare.
3. Double-click `Install.cmd`. Approve the administrator prompt. You see it only on the first install of this kind.
4. Start Flare. If House Style isn't enabled, select **File > Options > Plugins > House Style > Enable**, and then
   restart Flare.

The installer replaces a copy that you installed by hand. Your settings, your rule changes and your review decisions
are kept. From this version on, updates install themselves. See [Automatic updates](#automatic-updates).

## First-run setup and Settings

- A new writer's first House Style command opens a three-step setup. If you already have settings from 0.1, open it
  from **House Style > Settings > Run setup again**.
  1. **How will you use AI?** No AI (style rules only), your own Anthropic API key, or your company's AI service
     (gateway). **Test connection** checks the address and key.
  2. **Whose style rules?** Google's guide plus your own changes, or your team's shared style guide folder.
  3. **You're ready.** Finishing runs the command that you clicked.
- You can skip any step.
- Settings has four tabs: **AI**, **Style guide**, **Checking** and **Advanced**.
- The gateway address is cleaned up when you save: spaces and a trailing slash are removed, and `http://` becomes
  `https://`. Connection errors say what to check.
- The key field is called **Gateway key** for a gateway and **API key** for Anthropic.

## Check project

- Results are grouped by rule, most frequent first. Select a rule to see why it matters, examples and the files it's
  in.
- **Fix all** applies the rule's fixes in every file. You see the files and counts first. Nothing changes until you
  select **Apply**. A long run shows its progress, and **Stop after this file** stops it.
- **Review one by one** steps through one rule's suggestions.
- **Go to** opens the file and selects the text. **Open file** opens the topic or snippet. Right-click a suggestion for
  **Go to**, **Open file** and **Copy file path**.
- **By file** lists every suggestion file by file. The pane remembers your choice.
- If you undo a fix with Ctrl+Z, or reject it in Flare's **Review** tab, the suggestion comes back.

## Style rules

- **Style rules** on the ribbon lists every rule from Google, your team's guide, your own changes and the open
  project. Search by any word, and filter by source, state, content and whether a rule has a fix.
- Select a rule to see its wording, examples, level, where it applies, and who changed it, when and why. Rules have
  readable names.
- **Turn off…**, **Change level…** and **Turn back on** work from here. Turning a rule off offers the other rules that
  flag the same words. Turning it back on offers the rules that were turned off with it.
- Turning off a rule now works for every writer, with no administrator rights. Without a team guide, your changes are
  kept in your own settings folder.
- The window remembers its size.

## Team style guides

- Keep the team's guide in a shared folder: OneDrive, SharePoint, Google Drive or a network drive. Source control is
  optional.
- `FlareAI/owners.txt` in the guide lists the owners. Give owners write access to the folder and other writers read
  access.
- Writers who can't change the guide see **Request a change…** instead of **Turn off rule…**. Owners approve or
  decline requests in **Tune style guide**. The writer sees the answer on their next check.
- An exception for one project goes to the owners too.
- If `owners.txt` exists but can't be read, every change goes to the owners as a request.
- If the team's guide can't be read, House Style checks with Google's guide and says why.
- House Style's default changes to Google's rules reach team guides too.
- A guide's owners can publish it to Confluence Data Center. See
  [Publish the style guide to Confluence](../user-guide/Content/publish-guide.htm).

## Build style guide

- **Add notes or an old guide…** reads Word files (`.docx`), Word web pages (`.htm`), `.txt` and `.md`.
- **Extract rules** is the main button in the notes window.
- Edit or remove a suggested rule before you add it.
- A file that's still open in Word no longer causes an error.

## AI

- Reviews are reused after you apply fixes, prompts are smaller, and alt text and topic assists don't send the style
  guide. For a typical team, the estimated AI cost is about half of the previous version. See
  [AI cost](../testing/ai-cost.md).
- **Validate style guide** checks only your team's rules with AI. To include Google's rules too, select **Include
  Google's rules**.
- An AI suggestion that changes *must*, *should* or *may*, or a code term, isn't applied for you. You decide.
- Suggested alt text is 125 characters or fewer.
- With **No AI** chosen, earlier AI suggestions are hidden, and the pane says "AI review is off".

## Automatic updates

- Once a day, House Style asks GitHub whether a new version exists. No document text, key or identifier is sent.
- A notice offers **Update now**. The download is checked against the release's SHA-256 checksum. It installs when you
  close Flare, with no administrator prompt.
- If an update can't install, you stay on your current version, and a notice says why.
- After an update, **What's new** shows the changes. You can open it any time from the ribbon.
- To turn updates off, clear **Keep House Style up to date** on the **Advanced** tab of Settings. Your IT department
  can turn them off for everyone with an `update-policy.json` file. See [Privacy](https://abmorrill4.github.io/flare-ai-plugin/privacy.html#updates).

## Other fixes

- House Style writes its own errors to `%APPDATA%\FlareAI\diag.log`.
- The Plugins list in Flare shows the real version number.
- Export for LLMs keeps block quotes, drops script links, and writes plain summaries in `llms.txt`.

## Known issues

- **Check again** doesn't ask the AI again for paragraphs that haven't changed. It shows the saved review.
- After an AI edit of a paragraph that contains a variable, Ctrl+Y (redo) can make Flare show an error. Ctrl+Z works.
- **Rewrite…** can't restructure a paragraph that has pending tracked changes. Accept or reject them first.
