Publish the style guide to Confluence

The Flare style guide project is the source of truth. Confluence holds a published copy so other teams can read the guide there. Edit the guide in Flare; never edit the Confluence pages, because the next publish overwrites them.

Before you start

  1. Create a personal access token in Confluence (profile, Personal Access Tokens). The token's user needs permission to view the parent page and to add and edit pages in the space.
  2. Create an empty parent page for the guide and note its page ID (page menu, Page Information, or the number in the page URL).
  3. In Windows PowerShell, set the connection. Don't put the token in a file that is shared or committed.
    $env:CONFLUENCE_BASE_URL = "https://wiki.example.com/confluence"
$env:CONFLUENCE_PAT = "<your token>"
$env:CONFLUENCE_PARENT_ID = "123456"

Publish

  1. Dry run: .\scripts\publish-guide-to-confluence.ps1 -WhatIf. This lists the pages and writes the converted XHTML to confluence-preview. It doesn't contact Confluence.
  2. Publish to a test space first: add -SpaceKey TEST and a parent page ID in that space.
  3. Open one page. It starts with an "Edited in Flare" banner and links between guide pages work.
  4. Publish for real: .\scripts\publish-guide-to-confluence.ps1. Run it again after each guide change: only changed pages are updated.

Add -Folders Company to publish only your company rules. Topics you remove from the guide stay in Confluence, labelled flare-orphaned; delete them there when you are ready.

Publish the guide as HTML5 too

The guide project has an HTML5 target. In Flare, choose Build, select HTML5, then Publish if you also want a standalone copy on your intranet. After the Google guide is refreshed, run scripts\update-guide-toc.ps1 so the table of contents lists every page.
