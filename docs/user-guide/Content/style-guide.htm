Maintain the style guide

The style guide is a Flare project that your team keeps in source control. It has two folders under Content/Resources/StyleGuide:

  • Google: the Google developer documentation style guide, compiled into rules, one topic for each Google page. The plugin updates this folder when Google changes its guide. Don't edit it.
  • Company: your team's rules, shown in the pane as Our rules. Where they disagree with Google, your rules win.

Both folders use the same format. Each topic holds rules as short sentences with Bad and Good examples, and rule tables of words to avoid with their replacements. The About topic in the Company folder explains the format.

Change a Google rule

To turn a rule off or change how strict it is, select a suggestion that uses the rule in the review pane, and then select Turn off this rule…. Choose whether the change is for the whole team or this project only, the new level, and why. For the team, the plugin writes the change into the style guide's Changes to the Google guide topic; commit it so everyone gets it. A rule that's off is used by neither the checker nor the AI. To replace a Google rule, also write your own rule in a Company topic.

The guide ships with defaults for teams that write Flare help: rules that fit hand-written web pages or are debatable for help topics, such as "this page" to "this document", curly quotation marks, nonbreaking spaces and hyphens, and HTML tag and entity rules. Each is a row in that topic with its reason. Select Turned-off rules to see them, and turn any back on. Timeless-Documentation rules stay on; turn them off for a release-notes project only.

Writers who aren't style guide owners see Suggest changing this rule… instead: it is a request: it asks the owners, with the reason.

Browse every rule

To read the whole guide in one place without waiting for a suggestion, select Style rules on the ribbon (or Style rules… in Tune style guide). Every rule from Google, Company, your team's guide, your own guide and the open project is listed once, grouped by source and page. Search by any word or by a rule's reference, and filter by source, state (on, off, level changed), whether its suggestions carry a fix, and the content it applies to.

Select a rule to see its text, its Avoid and Use words or pattern, its Bad and Good examples, its level, where it applies, and its state with who changed it, when and why. Changes that ship with House Style are labelled Default. Rules that flag the same words list each other, so turning one off can include the others.

Turn off…, Change level…, Turn back on and Use the default work like the review pane: owners change the guide directly, and writers on a team guide they can only read send a request to the owners, with a reason. An exception for this project only also goes to the owners.

Rule references

Every rule has a permanent reference that the team's review decisions are tied to. You never type or manage it. When you validate the guide, the plugin gives new rules, and copies of rules, a reference of their own. Adding, moving or rewording rules doesn't move decisions from one rule to another.

Say where a rule applies

A rule applies to every topic unless you tag it. Tag a rule with Flare condition tags, the same way you tag any content:

  • Content tags limit a rule to sections with that kind of content, such as Steps, Code, Numbers or UI. The AI gets the rule only when a section contains that content.
  • Product tags limit a rule to products. The Product tag set in the style guide project lists the products your guide covers. Rules for other products, such as Google's rules for Android documentation, never apply until you add that product to the list.

Check the guide

After you edit the guide, select House Style > Validate style guide. It tests every rule table against its examples, finds rules that contradict or repeat each other, including between the Company and Google folders, and flags changes to Google rules that name a rule that doesn't exist. Check prose rules with AI… shows which written rules the AI applies.

Build rules from evidence

Select House Style > Build style guide:

  • Mine this project finds where topics disagree with each other, such as competing spellings or terms, and shows counts and example sentences. Pick the form to keep.
  • Add notes or an old guide… turns notes, an old style guide, or another tool's prompt into rules that quote where they came from.

Tune rules from review decisions

Select House Style > Tune style guide. It collects the team's accept and reject decisions. It lists rules that writers disagree on, rules that writers often reject, edits several writers keep making, and requests to turn a rule off, each with its evidence. Draft a change with AI rewrites a rule from that evidence as tracked changes in the guide.

Tune lists a rule only when enough writers made decisions on it, so one writer's taste doesn't change a shared rule.
