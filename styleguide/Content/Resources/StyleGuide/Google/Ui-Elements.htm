UI elements and interaction

Compiled from the Google developer documentation style guide, UI elements and interaction, licensed CC BY 4.0. Generated: edit the company rules instead, and turn Google rules off or change them there.

Focus on the task

  • When practical, state instructions in terms of what the reader should accomplish, rather than focusing on the widgets and gestures.
    • Good: Refresh the page.
  • Know the audience and provide the level of detail about UI elements and gestures that seems useful for the intended audience.
    • Good: To expand the Advanced options section, click the arrow_right expander arrow.

Format names of UI elements

  • When referring to any UI element by name, put its name in bold.
    • Bad: In the New Project window, select "New Activity", and then click the "Next" button.
    • Good: In the New project window, select the New activity checkbox, and then click Next.
  • Don't use code font for UI elements, unless it's an element that meets the requirements for code font; in that case, use both code font and bold.
  • Don't make an official feature name or product name bold, except when it directly refers to an element on the page that uses the name, such as a window title or button name.
  • If you document a UI element outside the context of a procedure, try to provide context for the element.
    • Bad: The service lets you check the status of all jobs in the Current jobs section.
    • Good: The service lets you check the status of all jobs in the Current jobs section of the service console.

Use appropriate capitalization

  • In most cases, follow the capitalization of UI labels as it appears on the page.
  • When a label is all uppercase, use sentence case.
    • Bad: Click REFRESH.
    • Good: Click Refresh.
  • When referring to multiple labels that are inconsistently cased, use sentence case for all of the labels.
    • Bad: Click NEW PROJECT, and then click New Activity.
    • Good: Click New project, and then click New activity.

Refer to UI elements

  • Don't use UI elements as if they were English verbs or nouns.
    • Bad: Save the settings.
    • Good: To save the settings, click Save.

Terminology and usage

  • In general, focus on the feature and its functionality, not the UI element; use the name of the UI element only if it adds clarity for the reader.
    • Good: Go to File > Tools.
  • Don't use slang terms for UI elements—for example, hamburger icon or zippy.
    • Bad: To expand the Advanced options section, click the zippy.
    • Good: Expand Advanced options.

Windows, pages, dialogs, panes, and sections

  • Use window for the entire application window in a desktop environment or for modular application elements that you can open and close, not page.
    • Bad: In the MyApp page, click Edit.
    • Good: In the MyApp window, click Edit.
  • Use page when referring to a web page in general and to a subpage of a console in particular.
    • Bad: In the Google Cloud console, go to the Deployments window.
    • Good: In the Google Cloud console, go to the Deployments page.
  • Use dialog for a smaller window that is usually detached from the main application window and appears in front of it.
    • Bad: In the Welcome pop-up window, click OK.
    • Good: In the Welcome dialog, click OK.
  • Do not use terms such as window, section, area, or column to refer to a pane or panel.
    • Bad: In the Create service account section, click New.
    • Good: In the Create service account pane, click New.

Menus and menu bars

  • To refer to an item in a menu, use the term command, not choice, menu item, or option, unless you're documenting how to build an interface.
  • To refer to a menu, use the form the LABEL_NAME menu.
  • To tell the reader where to find a command in a menu or submenu, use a phrase like In the File menu, select Open.
    • Good: In the File menu, select Open.
  • Don't use drop-down as a synonym for menu.

Use angle brackets

  • If you use angle brackets (>) for a menu sequence, put a nonbreaking space (&nbsp;) before each angle bracket.
  • Don't bold each menu name separately; instead, enclose the entire angle-bracket sequence in a single bold tag.
  • Wrap each angle bracket with a span tag and add an aria-label attribute with and then text, for example <span aria-label="and then">></span>.

Markdown

  • Use angle-bracket notation only for menu items; don't use it to describe a combination of different UI elements.
    • Bad: Select MyApp > Preferences > Languages > + > CSS.
    • Good: Select MyApp > Preferences, and then select the Languages preference pane.

Navigation menu

  • Use navigation menu for a control that contains a list of items to go to pages in an application or website; don't use the terms navigation bar, navigation pane, navigation panel, or navigation window for such a control.
    • Good: In the BigQuery navigation menu, click Scheduled queries.

Toolbar

  • Refer to the toolbar by name if you think that the user needs help finding a button.
    • Good: On the Google Cloud console toolbar, click notifications_none Notifications.
  • Call a toolbar button that includes a menu a menu button.

Buttons and icons

  • To refer to a button, use the button's label.
    • Bad: Click the "OK" button.
    • Good: Click OK.
  • If the button includes an icon, write the name of the button as shown in the tooltip, and add the button icon before the name.
    • Bad: Click more_vert.
    • Good: Click more_vert Settings and utilities.
  • If you need to use a space between the icon and the button name for readability, use a nonbreaking space.
  • If the icon tooltip is identical to the name of the icon, use an empty alt attribute.
  • If a UI element name ends with an ellipsis (...), leave out the ellipsis.
    • Bad: Click Browse....
    • Good: Click Browse.
  • Don't use directional language to orient the reader, such as above, below, or right-hand side.
    • Bad: In the left-side panel, click the button with three lines.
    • Good: Click menu Menu.

Difficult-to-find UI elements

  • If a UI element is hard to find, provide a screenshot.
    • Good: In the list of services, click view_column Column display options.
  • For difficult-to-find UI elements, use the button icon along with its name as shown in the button tooltip instead of directional language.
    • Good: Click refresh Refresh.
  • Add context to help the user find a difficult-to-find element.
    • Good: On the Cloud Run toolbar, click refresh Refresh.

Tab

  • To refer to a tab, use the form the LABEL_NAME tab.
    • Good: Select Tools > Options, and then click the Edit tab.

Text box

  • To refer to a text box, use box and the form the LABEL_NAME box.
    • Good: In the Owner box, enter your name.
  • Format the text that the user types by using the code element in HTML, or by using code formatting (monospace) in other markup.
    • Good: In the Name box, enter wsfc-1.
  • In Google Cloud and Google Workspace documentation, use field instead of box.
    • Good: In the Instance field, specify a value less than 64 characters long.

List box, combo box, and spin box

  • To refer to a list box, use the form the LABEL_NAME list or the LABEL_NAME box, whichever is clearer.
    • Good: In the Item list, select Desktop.
  • To refer to a combo box, use the form the LABEL_NAME box.
    • Good: In the Font box, type or select the font that you want to use.
  • To refer to entering a value into a combo box, use the verbs type or select or enter.
    • Good: In the Font box, type or select the font that you want to use.
  • To refer to a spin box, use the form the LABEL_NAME box.
    • Good: In the Font Size box, enter a font size.
  • To refer to entering a value into a spin box, use the verb enter.
    • Good: In the Font Size box, enter a font size.

Checkbox

  • To refer to a checkbox, use the form the LABEL_NAME checkbox.
    • Good: Select the Automatically check for updates checkbox.
  • Be wary of using the verbs check and uncheck for checkboxes; it's often best to use select and clear instead.
    • Good: Clear the Bookmarks checkbox.
  • If you need to refer to the state of a checkbox, refer to it as selected or not selected.
    • Good: Make sure that the Bookmarks checkbox isn't selected.

Radio button

  • To refer to a radio button, use the radio button's label, or refer to the group of buttons by its label.
    • Good: For Startup mode, select an option.

Expander arrow

  • Avoid referring to expander arrows explicitly, but when you do, use the terms expander arrow and expandable section rather than terms like expando or zippy.
    • Bad: To expand the Advanced options section, click the zippy.
    • Good: To expand the Advanced options section, click the arrow_right expander arrow.

Toggle

  • Don't use the word toggle as a verb; describe the action that you want the user to take.
    • Good: To turn on the setting, click the Wi-Fi toggle.
  • If you might not know what state the toggle is in before the user interacts with it, be clear what position the toggle should be in.
    • Good: In Settings, click the Magic mode toggle to the on position.

Press and type keyboard keys

  • To indicate that the user should press a given keyboard key or combination, use the kbd element.
    • Good: Press <kbd>Control+C</kbd>.
  • If you're working with non-HTML markup, use monospace formatting for keys, which is how the kbd element renders.
  • To refer to a letter key, use uppercase instead of lowercase.
    • Bad: To save, press Control+s.
    • Good: To save, press Control+S.
  • To refer to a key that the user types to enter that key's value as text input, use the code element, not the kbd element.
  • To refer to a keyboard key, use the key's name; if that's ambiguous, use the form the KEY_NAME key.
    • Good: Press the Esc key.
  • Spell out the names of modifier keys such as Command, Control, Option, and Shift, and don't use symbols for those keys.
    • Bad: To copy, press Ctrl+C (⌘+C).
    • Good: To copy, press Control+C (or Command+C on macOS).
  • To refer to a key combination, use the form MODIFIER+KEY_NAME.
    • Good: Press Control+V.
  • When you provide shortcuts for multiple operating systems, put the macOS shortcut in parentheses after the Windows and Linux shortcut.
    • Bad: To copy, press Ctrl+C (⌘+C).
    • Good: To copy, press Control+C (or Command+C on macOS).
  • To refer to a key or combination that uses the Shift key, use the form MODIFIER+Shift+KEY_NAME.
    • Good: Press Control+Shift+?.
  • Spell out the names of characters that could be confusing in a keyboard shortcut, such as comma, hyphen, period, and plus.
  • To refer to a keyboard shortcut, use either keyboard shortcut or key combination.
  • To refer to pressing a key or combination to cause an action to occur, use the verb press.
    • Good: Press Esc.
  • To refer to typing a key or combination as part of text, use the verbs enter or type.

Prepositions

  • Use the preposition in with dialogs, fields, lists, menus, panes, and windows.
    • Good: In the Alert dialog, click OK.
  • Use the preposition on with pages, tabs, and toolbars.
    • Good: On the Create an instance page, click Add.

Verbs in procedures

  • To describe an action on the page, use the following verbs: click, choose, drag, enable, enter, type, go to, hold the pointer over, press, select, tap, turn on, and turn off.
