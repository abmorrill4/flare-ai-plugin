Placeholder formatting

Compiled from the Google developer documentation style guide, Placeholder formatting, licensed CC BY 4.0. Generated: edit the company rules instead, and turn Google rules off or change them there.

Placeholders

  • In general, don't use a single x or a series of x's as placeholders; use a more informative placeholder, except in contexts (such as HTTP status codes) where a series of x's is the standard.

Placeholders in inline text

  • If your sample code and command placeholders occur in a sentence, wrap them by using the var element inside a code element, like this: <code><var>PLACEHOLDER_NAME</var></code>.
    • Good: <code><var>PLACEHOLDER_NAME</var></code>
  • If your placeholder does not represent a code sample or command, wrap it by using the var element, like this: <var>PLACEHOLDER_NAME</var>.
    • Good: <var>PLACEHOLDER_NAME</var>

Placeholders in code blocks

  • If your placeholders are in a block of code, wrap the code block in a pre element, and tag placeholders with var elements.
    • Good: <pre> gcloud compute forwarding-rules create <var>FORWARDING_RULE_NAME</var> \ --global | --region=<var>REGION</var> \ --load-balancing-scheme=<var>LOAD_BALANCING_SCHEME</var> \ --network=<var>NETWORK</var> \ ... </pre>

Placeholder text

  • Use uppercase characters with underscore delimiters in placeholder text.
    • Bad: .../<var>API-name</var>
    • Good: .../<var>API_NAME</var>
  • If the context in which your placeholders appear makes using uppercase characters with underscore delimiters a bad idea, use something else that makes sense to you, but be internally consistent.
  • Don't include possessive adjectives in placeholders.
    • Bad: .../<var>MY_API_NAME</var>
    • Good: .../<var>API_NAME</var>
  • Use uppercase characters with underscore delimiters in placeholder text.
  • Don't include possessive adjectives in placeholders.

Explain placeholders

  • When you use a placeholder in text or code, explain the placeholder the first time you use it.
    • Good: gcloud compute instances create INSTANCE_NAME --metadata enable-guest-attributes=TRUE Replace INSTANCE_NAME with the name that you want your new VM instance to have.
  • Repeat a placeholder explanation only when doing so might benefit the reader—for example, when your document is lengthy, you've introduced several other placeholders in a long procedure, or your document isn't intended to be read from beginning to end.

Single placeholder

  • For a single placeholder, use the format "Replace PLACEHOLDER with a description of what the placeholder represents."
    • Good: Replace BUILD_ID with the ID of the WORKING build that you copied in the preceding step.

Two or more placeholders

  • For two or more placeholders, follow the command line with a descriptive list of the placeholders used in the command line.
  • Explain what each placeholder represents even if the placeholder value is intuitive to you.
  • Introduce the list of command-line placeholders with "Replace the following:".
    • Good: Replace the following:
  • List the placeholders in the order in which they appear in the command line.
  • Tag each placeholder in a code sample or command with code and var elements; for non-code samples, remove the code elements.
    • Good: <li><code><var>INSTANCE_NAME</var></code>: description</li>
  • Follow each listed placeholder with a colon and a description that starts with a lowercase letter.
    • Good: ADMIN_PROJECT_ID: the project that owns the reservation
  • If the placeholder description contains an example, introduce it with an em dash or "such as".
    • Good: ZONE: a Google Cloud zone that's close to your location—for example, us-east1.
  • Make each item in the placeholder list follow the list style.

Placeholders in output

  • If you provide a code output example, explain any placeholders that appear in sample output.
  • Use var elements to identify the placeholder text in the output.
  • Follow the example output with a list of the placeholders used in the example.
  • Introduce the list of output placeholders with "This output includes the following values:".
    • Good: This output includes the following values:
  • List the output placeholders in the order in which they appear in the example.
  • Tag each output placeholder with a var element, followed by a colon and a description that starts with a lowercase letter.
    • Good: OPERATION_ID: the ID of the import operation
  • If an output placeholder description contains an example, introduce it with an em dash or "such as".
    • Good: SOURCE_FILE: the URI for the image in Cloud Storage—for example, gs://my-bucket/my-image.vmdk
