Cross-references and linking

Compiled from the Google developer documentation style guide, Cross-references and linking, licensed CC BY 4.0. Generated: edit the company rules instead, and turn Google rules off or change them there.

Choose links selectively

  • Be selective about which links you include on a page.

Provide context on the page

  • When possible, provide help in context rather than linking elsewhere, such as to define a term, briefly explain a concept, or provide a couple of steps.

Link to third-party sites

  • When the reader needs to know about third-party standards or software, provide a link rather than attempt to thoroughly document someone else's standards, but provide brief information on the page instead when possible.

Avoid duplicate links

  • Within a given page, don't provide duplicate links to the same destination; provide the link once where it's most useful, unless you're linking to a particular section, the page is very long and the links are far apart, or the page has multiple entry points such as procedure and troubleshooting sections.

Provide the most relevant link

  • Link to the most relevant page on a site and to the most relevant heading on a page.
  • Avoid providing multiple links that do the same job.

Write descriptive link text

  • For the link text itself, use short, unique, descriptive phrases that provide context for the material that you're linking to.
    • Bad: See this blog post.
    • Good: You can use Cloud Scheduler and Cloud Functions to manage task scheduling on Compute Engine.
  • Rework a sentence when needed to include a phrase that makes good link text.

Two options for effective link text

  • For your link text, use either the exact page title or heading that you're referencing, or a descriptive phrase.
    • Good: For more information, see Load balancing and scaling.

Descriptive phrases as link text

  • When you use a description of the destination page as link text, capitalize it as if it's part of the sentence.
  • Place important words at the beginning of the link text.
  • Don't use the same link text in the same document for different target pages.
  • Keep link text short where possible; don't write lengthy link text such as a sentence or short paragraph.

Avoid vague link text

  • Write link text that makes sense without the surrounding text; don't use phrases such as this document, this article, or click here.
    • Bad: For more information, see this document.
    • Good: For more information, see Make headings into link targets.

Avoid URLs as link text

  • In general, don't use a URL as link text; instead, use the page title or a description of the page (in some legal documents, such as some Terms of Service documents, URLs as link text are okay).
    • Bad: See the HTTP/1.1 RFC at http://www.w3.org/Protocols/rfc2616/rfc2616.html.
    • Good: For more information about protocols, see HTTP/1.1 RFC.

Include abbreviations in link text

  • If the text includes an abbreviation in parentheses, include the long form and the abbreviation in the link text.

Link to commands

  • If the text includes a command or another element usually conveyed with code font, include the description of the code element with the link text, unless doing so is awkward or redundant.
    • Bad: This service supports the GET method, HEAD method, and OPTIONS method.
    • Good: This service supports the GET, HEAD, and OPTIONS methods.

Write link introductions ("For more information")

  • When you dedicate a separate sentence to a cross-reference, introduce it with "For more information, see..." or "For more information about..., see... ."
    • Good: For more information, see Load balancing and scaling.
  • Include the "about..." clause when the link text or surrounding context doesn't clearly indicate why you're referring the reader to this information.
    • Good: For more information about task scheduling, see Reliable task scheduling on Google Compute Engine.
  • Use see to refer to links and cross-references.

Clarify the purpose of a link

  • Make sure that the surrounding context or the link text itself clearly indicates why you're referring the reader to this information; make the explanation specific, but don't repeat the link text.
    • Good: For more information about authentication and authorization, see Using OAuth 2.0 to access Google APIs.

Explain unexpected link behavior

  • If a link goes to an unexpected destination or behaves in an unexpected way, then provide that context.
  • If a link downloads a file or opens an email, then make that clear in the link text, and mention the file type.
    • Good: For more information, download the security features PDF.
  • When you're linking to another section on the same page, use a standard phrase to let the reader know that the link takes them to a different section of the same page.
  • When you're linking to a section heading on another page, use the same wording and formatting as you do in a regular cross-reference.
    • Good: For more information, see Create a table.
  • If the title of the section that you're linking to is identical to a title on the source page, add context to the cross-reference.
    • Good: For more information, see Install libraries in "Building new audiences based on existing customer lifetime value."

Open links in the current tab

  • Don't force links to open in a new tab or window; let the reader decide how to open links.
  • In the rare situation that a link needs to open in a new tab or window, let the reader know that the link opens differently than expected.
    • Bad: Accessible content
    • Good: Accessible content (opens in a new tab)
