Headings and titles

  • Use sentence case for headings and titles.
  • Use descriptive headings and titles.
  • Make headings and titles unique.

Heading and title text

  • Write document titles based on the primary purpose of the document.
  • Write section headings based on the type of content that's in the section.
  • For a task-based heading, start with a bare infinitive.
    • Bad: Creating an instance
    • Good: Create an instance
  • For a conceptual or non-task-based heading, use a noun phrase that doesn't start with an -ing verb.
    • Bad: Migrating to Google Cloud
    • Good: Migration to Google Cloud
  • If a section is not required for all users or scenarios, use the Optional: prefix in the heading.
    • Bad: Customize your alias (optional)
    • Good: Optional: Customize your alias

Title phrasing

  • Use a unique level-1 heading (h1) for each page in a set of documents.
  • Only use a level-1 heading once on a page.
  • Avoid repeating the exact page title in a heading on the page.
    • Good: Create and start VM instances, with section headings Create a VM and Start a VM

Mixed heading styles

  • If a single document includes both task-based and conceptual sections, use the appropriate phrasing for each section's heading.
    • Good: <h1>Log serving requests by using AI Platform Prediction</h1> <h2>ML model monitoring overview</h2> <h2>Configure notebook settings</h2>

Use of -ing verb forms

  • When possible, avoid using -ing verb forms as the first word in any heading or title.
    • Bad: Transferring data sets
    • Good: Transfer data sets
  • It's OK to use a gerund such as Billing or Pricing when there isn't a better alternative.
    • Good: Billing
  • It's OK to use an -ing verb form later in a heading or title.
    • Good: Introduction to BigQuery monitoring

Heading and title format

  • Apply the guidance for standard text, such as contractions and articles, to headings.

Syntax and capitalization

  • Keep punctuation in headings simple; if a heading needs complicated punctuation, consider rewriting it.
  • Only use an abbreviation of a word in a page title or heading if it's the more commonly known version of the word.
  • If you use an abbreviation in a heading, define the abbreviation in the first instance of the word in a paragraph.
  • For SEO, use the more prominent version of a term in headings.

Formatting and code

  • Don't use numbers in headings to indicate a sequence of sections; rely on heading hierarchy and order instead.
  • Avoid code items in headings.
  • If you must mention a code item in a heading, add a descriptive noun to the item in code font.
  • Don't put links in headings.

Hierarchy and structure

  • Don't use heading tags to change visual formatting; use CSS rather than a heading level that doesn't fit the hierarchy.
  • Don't make up your own formatting for headings.
  • Use heading tags to structure your content hierarchically.
  • Don't skip levels of the heading hierarchy; for example, put an h3 tag only under an h2 tag.
    • Bad: <h1>Transfer data sets</h1> <p>This document provides a high-level overview of ways to transfer your data to Google Cloud.</p> <h3>Estimate costs</h3>
    • Good: <h1>Transfer data sets</h1> <p>This document provides a high-level overview of ways to transfer your data to Google Cloud.</p> <h2>Estimate costs</h2>
  • Don't use empty headings; make sure headings are followed by content.
    • Bad: <h2>Migrate VMs to Compute Engine</h2> <h3>Design the migration</h3>
    • Good: <h2>Migrate VMs to Compute Engine</h2> <p>Migration is not just a single step. The following sections describe the recommended steps.</p> <h3>Design the migration</h3>

Refer to a group of sections

  • If you introduce a group of related H3 or lower sections within a larger H2 section, use the phrase the following sections.
    • Good: The following sections describe the views in the data preparation editor.
  • Don't refer to a group of subsections using the phrases this section or these sections.
