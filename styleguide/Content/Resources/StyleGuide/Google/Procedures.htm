Procedures

Introductory sentences

  • In most cases, introduce a procedure with an introductory sentence that provides context to the reader that isn't part of the section heading.
  • Don't simply repeat the heading: if the heading explains what the procedure is, and no additional context is needed, then don't include an introductory statement.
  • End the introductory sentence with a colon if it immediately precedes the procedure.
    • Good: To customize the buttons, follow these steps:
  • End the introductory sentence with a period if there's more material (such as a note paragraph) between the introduction and the procedure.
  • Don't introduce a procedure with a partial sentence that's completed by the numbered steps; you can use an imperative statement or a complete sentence instead.
    • Bad: To customize the buttons:
    • Good: To customize the buttons, follow these steps:

Single-step procedures

  • When a procedure consists of only one step, write the step in one sentence and format it as a bulleted list.
    • Bad: To clear (flush) the entire log, follow this step: 1. Click Clear logcat.
    • Good: To clear (flush) the entire log, click Clear logcat.

Sub-steps in numbered procedures

  • In a numbered procedure, label sub-steps with lowercase letters, and label sub-sub-steps with lowercase Roman numerals.
  • When a step has sub-steps, treat the step like an introductory sentence: put a colon or a period at the end of the step, as appropriate.
    • Good: For Name, enter a name for the VM instance, and then do the following:

Order of multiple components in a step

  • To document a complex procedural step, use the following order: describe the action to take; list a command, if necessary; explain any placeholders used in the command; explain the command in more detail, if necessary; list the output of the command, if necessary; in a separate paragraph, explain the result of an action, or any output, if necessary.

Multi-action procedures

  • In general, use one step for each action.
  • You can combine small actions into one step by using angle brackets (>) for sequential menu selections.
    • Good: Click File > New > Document.
  • Don't make the steps too long; if they feel too long, consider splitting them into multiple steps.

Multiple procedures for the same task

  • If there's more than one way to complete a task, then document one procedure that's accessible for all readers.
  • Choose a procedure that lets readers do all the steps by using only a keyboard.
  • If all methods are accessible, pick the shortest and simplest approach if possible.
  • Choose a procedure that uses a programming language that most of your audience is familiar with.
  • If you need to document multiple ways to complete a task, then separate them in different pages, headings, or tabs.

Repetitive procedures

  • Avoid repeating procedures; instead, reference those procedures and link to them.
    • Good: Create a user as you did in the previous step.

Optional steps

  • For an optional step, at the beginning of the step, type Optional followed by a colon.
    • Bad: (Optional) Type an arbitrary string ...
    • Good: Optional: Type an arbitrary string ...

Steps that say where to complete a task

  • Tell the reader where to complete an action—for example, in a particular tool or UI field—before you state the action.
    • Bad: Go to the Monitoring page in the Google Cloud console.
    • Good: In the Google Cloud console, go to the Monitoring page.
  • If a set of procedures is split across multiple headings, then in each procedure, restate where the reader completes the action, even if the context is the same as in the previous procedure.
    • Good: In the Google Cloud console, go to the BigQuery page.

Summary of guidelines for writing procedures

  • Set the context (such as a tool or an environment) in which the reader performs a procedure.
    • Good: In Cloud Shell, connect to the development cluster.
  • Write in the order that the reader needs to follow.
  • Make sure that the first sentence in a procedural step includes an imperative verb.
    • Bad: You need the project ID later in this document. Retrieve the project ID.
    • Good: Clone the repository that contains the sample data.
  • Use complete sentences.
  • Use parallel structure and consistent verb form.
    • Bad: Download the service account key to your local machine by clicking More and then clicking Download file.
    • Good: Download the service account key to your local machine. Click More, and then click Download.
  • Don't use directional language to orient the reader, such as above, below, or right-hand side.
    • Bad: In the above diagram, ...
    • Good: In the preceding diagram,...
  • If a UI element is hard to find, provide a screenshot instead of describing its position or appearance.
    • Bad: Click the button with three lines.
    • Good: Click menu Menu.
  • Avoid using "run the following command" to introduce code; instead, focus on what the command does.
    • Bad: In Cloud Shell, deploy the load generator by running the following command:...
    • Good: In Cloud Shell, deploy the load generator:...
  • If the reader must press Enter after a step, then include that instruction as part of the step.
    • Bad: Click the search box and type custom function. Press Enter.
    • Good: Click the search box, type custom function, and then press Enter.
  • Don't include keyboard shortcuts.
    • Bad: Press Ctrl+C, and then press Ctrl+V...
    • Good: Copy the command, and then paste it...
  • When there's more than one way to do something, give only the best way.
  • Ensure that the reader has the information that they need in order to prepare for the task ahead of time.
    • Good: The following hardware and software are required:...
  • Include as few steps as possible to complete the task.
  • Limit interruptions in the path.
  • Focus on one reader decision at a time.
  • Separate each instruction by making each instruction a separate list item.

Steps with goals

  • When a step includes a goal, state the goal before the action.
    • Bad: Click File > New > Document to start a new document.
    • Good: To start a new document, click File > New > Document.
  • If the "To ..." format can imply that a required step is optional, state the goal followed by a colon and then the action; otherwise prefer the more natural "To ..." format.
    • Good: Start a new document: click File > New > Document.

Steps with results or justifications

  • State the action first and the result second, and keep the result in the same paragraph as the action.
    • Good: Click Run. The query results appear after the query runs.
  • Consider whether you can avoid repetitiveness and overwhelming the reader with too much bolding of UI elements when stating results.
    • Bad: Click Enter. The New file dialog appears. In the New file dialog, click Next.
    • Good: Click Enter. In the New file dialog that appears, click Next.
  • When a step includes a justification for why the step is important, state the action first and the justification second.
    • Good: Store the private key in a secure location. You need it later.
