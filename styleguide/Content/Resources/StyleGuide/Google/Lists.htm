Lists

Compiled from the Google developer documentation style guide, Lists, licensed CC BY 4.0. Generated: edit the company rules instead, and turn Google rules off or change them there.

List or table?

  • Don't use a list to show only one item; if you want to set a single item off from surrounding text, use some other formatting.

Types of lists

  • Use a numbered list for a set of items where the sequence is significant, such as ordered steps, phases, or priorities.
    • Good: Here's a sequence of steps to follow: 1. Open the box. 2. Remove the bobcat from the box. 3. Feed the bobcat.
  • Label nested sequential lists with lowercase letters or lowercase Roman numerals.
    • Good: Here's a list of things to do after breakfast, in order: 1. Go shopping. a. Buy groceries: Flour, Eggs, Sugar, Butter b. Go to mall: i. Buy dress. ii. Buy shoes. 2. Make cake. 3. Build birthday present out of spare parts. 4. Clean house.
  • Use a bulleted list for a set of items that's not a sequence, such as a set of nonsequential options or examples.
    • Good: Here's a list of things that can go wrong, in no particular order: • Your bicycle might explode. • The sun might go out. • An ant might break its leg and require a tiny splint.
  • In a bulleted list, make sure it's clear whether or not every item is required.
  • Use a description list for a set of terms, each with a description, definition, or explanation, when you want to draw attention to two or more terms (such as a glossary).
    • Good: Here are some descriptions of types of birds: Emu: The best kind of bird. Crow: The other best kind of bird. Peacock: Also the best kind of bird. Phoenix: An even better kind of bird.
  • Use a description list with bulleted run-in headings for a set of introductory terms or phrases, each followed by a description, when you want to highlight and explain several concepts or save space.
    • Good: Here are some descriptions of types of birds: • Emu: the best kind of bird • Crow: the other best kind of bird • Peacock: also the best kind of bird • Phoenix: an even better kind of bird

Multiple paragraph list items

  • To create multiple paragraphs in a list item, use the p element rather than using the br element.

Introductory sentences for lists

  • Introduce a list with the appropriate context; in most cases, precede a list with an introductory sentence.
  • End the introductory sentence with a colon if it immediately precedes the list, and usually with a period if there's more material (such as a note paragraph) between the introduction and the list.
  • If the list doesn't need any additional context other than the heading that immediately precedes the list, it's OK to not introduce the list with an introductory sentence.
    • Bad: Objectives In the following tutorial, you will complete the following tasks: Create an instance Snapshot an instance Delete an instance
    • Good: Objectives Create an instance Snapshot an instance Delete an instance
  • Introduce a list with a complete sentence, not a partial one that's completed by the list items; you can also use "the following" as a noun phrase.
    • Bad: Use the Submit button to: Submit the form. Indicate that you're done. Allow the next person to enter their data.
    • Good: Use the Submit button for any of the following purposes: To submit the form. To indicate that you're done. To allow the next person to enter their data.

Unusual list numbering

  • To present a list in reverse-numerical order, use an ol element with a reversed attribute.
  • In most cases, don't manually number a list item in a numbered list with the value attribute, because if the number of items changes later, you'll have to manually change the value.

Parallel syntax

  • Use the same syntax/structure for all list items in a given list, if possible.

Numbered, lettered, and bulleted lists

  • Start each list item with a capital letter, unless case is an important part of the information conveyed by the list—such as in a list of glossary terms.
  • End each list item with a period or other appropriate sentence-ending punctuation, except for items that are a single word, have no verb, are entirely in code font, or are entirely link text or a document title. If you're writing UI text rather than prose documentation, follow the Material Design guidelines instead.
    • Good: You can do any of the following by using the API: Create an item. Replace one item with another. Update an item. Delete an item.
  • If the list item consists of a single word, don't add end punctuation.
    • Good: The following words are adjectives: Big Small Gratuitous
  • If the list item doesn't include a verb, don't add end punctuation.
    • Good: The SDK supports the following UI elements: Text box Bulleted list Button
  • If the list item is entirely in code font, don't add end punctuation.
  • If the list item is entirely link text or a document title, don't add end punctuation.
  • If you end up with inconsistent punctuation in your list, either rewrite your list to use parallel construction or add end punctuation to every list item for consistency.

Description lists

  • Don't add an explanatory phrase to only a single list item; instead, use a description list, and provide explanatory phrases for all items.
    • Bad: The following words are adjectives: Big Relevant Gratuitous Purple—this is a color.
    • Good: The following words are adjectives: Big: A short word. Relevant: A fancy word. Gratuitous: A long word. Purple: A vibrant color.
  • In most contexts, start each term (dt element) in a description list with a capital letter.
  • Don't end the term (dt element) in a description list with a period.
  • Generally put a period at the end of each dd (description) element.

Description lists that use run-in headings

  • In most contexts, start the run-in heading with a capital letter.
  • End the run-in heading with a period or a colon, but be consistent within the list.
  • If the description text follows a period, start the text with a capital letter and end the description with a period.
    • Good: Budget Airlines reduces your ticket cost in several ways: • It increases fuel economy by reducing baggage weight. By charging astronomical prices for anything larger than a wallet.... • It carries more passengers per flight. By reducing leg room to industry and medical minimums, it fits more seats....
  • If the description text follows a colon, start the text with a lowercase letter.
    • Good: The following words are adjectives: • Big: a short word • Relevant: a fancy word • Gratuitous: a long word • Purple: a vibrant color
  • If the description follows a colon and is a list of items or short phrases without verbs, don't include a period.
    • Good: The coffee shop has several great choices: • Coffee: latte, mocha, cappuccino, espresso, macchiato • Tea: chai tea, chai latte, black tea, green tea, herbal tea
  • If the description follows a colon and includes a verb or expresses a standalone thought, end the description with a period.
  • Don't use a dash to set off a description from an item in a description list; use a colon instead.
    • Bad: Purple—this is a color.
    • Good: Purple: a vibrant color

Comma-separated lists

  • When you write a list in a paragraph, use serial commas to separate the items.
    • Good: The service processes data like event logs, clickstream data, social network interactions, and ecommerce transactions.
  • Avoid ending a list with etc. or phrases like and so on; instead, introduce the list in a way that makes it clear that the list isn't all-inclusive.
    • Bad: The service processes event logs, clickstream data, social network interactions, e-commerce transactions, etc.
    • Good: The service processes data like event logs, clickstream data, social network interactions, and ecommerce transactions.
