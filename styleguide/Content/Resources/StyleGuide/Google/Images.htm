Figures and other images

  • Use images only when they provide useful visual explanations of information that is otherwise difficult to express with words.
  • For screenshots, be discreet: only capture UIs that are important to the discussion.

Create and save images

  • Don't use images of text, code samples, or terminal output; use actual text.
  • For diagrams, use SVG files if possible because SVGs stay sharp when you zoom in on the image.
  • If you don't have an SVG file, save your diagram as a PNG file unless you have a good reason to use a different format.
  • Regardless of the format, don't use a transparent background for diagrams.
  • For animations and videos, don't use animated GIF; use a more resource-efficient format such as MP4.
  • Be consistent for a given document or doc set in what operating system you use for screenshots.
  • Be consistent in how your screenshots look; for example, if some screenshots include drop shadows of the main window, make similar screenshots consistent.
  • Crop screenshots to show the relevant information; don't include the full window if you just want to show a single button or menu item.
  • Don't include personally identifying information (PII) in screenshots.
  • If a source screenshot includes PII, hide it with a solid-color overlay with 100% opacity, not blurs, mosaic effects, or similar image-processing effects.
  • If you're exporting an image to a format that can include information on separate layers (for example, PDF or TIFF), flatten the image on export.
  • Don't use image maps; instead, provide a list of text references following the image.
  • Use descriptive filenames for your image files.

Text associated with images

  • Always introduce an image with a complete sentence, except for screenshots that immediately follow procedural text that describes a UI.
    • Good: The following diagram shows how you can apply bounded contexts to an existing ecommerce application:
  • End the sentence that introduces an image with a colon if it immediately precedes the image, or usually with a period if there's more material (such as a note paragraph) between the introduction and the image.

Alt text

  • Write alt text as a concise description of the image that can replace the image in situations where the image isn't visible.
  • If the image is decorative or it's provided only as a visual aid for information that is already expressed in text, provide empty alternative text (alt="") so it's ignored by assistive technologies.
  • When using the img element, always include the alt attribute, even if its assigned value is an empty string (alt="").
  • If the alternative text is redundant with surrounding text or it's not useful to visually impaired readers, use the empty tag (alt="").
  • Don't include phrases like Image of or Photo of in alt text.
  • Include punctuation in alt text.
  • Use consistent alt text for repeated instances of an image, such as controls, status indicators, or icons that appear multiple times in your document.
  • When possible, avoid using all-caps in alt text.
  • Introduce diagrams in the text, not in the alt text.
  • Don't use figure captions to replace alt text.
  • Use full sentences or a noun phrase in alt text.
    • Good: alt="Architecture of an app that's built with Apps Script."
  • Write short, descriptive alt text in 155 characters or less.
  • If the image presents more useful information than you can fit in 155 characters, include a brief summary in the alt attribute and a more extensive description of the image in the text.
  • Write alt text that considers the context of the image, not just its content.

Figure captions

  • When using the figcaption element, wrap both the figcaption and img elements in the figure element.
  • If you use figure numbers, use the form "Figure NUMBER. DESCRIPTION." with the figure label in bold.
    • Good: Figure 1. Application capabilities are separated into bounded contexts that migrate to services.
  • Use complete sentences in figure captions.
    • Bad: Bounded contexts
    • Good: Application capabilities are separated into bounded contexts that migrate to services.
  • Always use end punctuation for captions.
  • When you refer to a figure, don't use spatial descriptions such as "the image above."
  • If you used figure numbers, consistently refer to the figure by number, for example "... as shown in figure 1."
    • Good: ... as shown in figure 1.
  • If you can't use figure numbers, show the figure again instead of referring back to it.
  • Don't include the figure caption in a sentence referencing the figure.

Figure descriptions

  • Convey any new information through text; don't introduce it in a figure or image.
  • In a figure description, create text that conveys the same information as the figure.
  • Use a figure description when a figure caption doesn't convey the purpose or complete information of the figure.
  • Use punctuation in figure descriptions.

Text in figures

  • In most cases, avoid embedding explanatory text in screenshot graphics.
  • If you must embed text in an image, also provide the same information in a form that people with visual disabilities can use, such as a figure description.
  • Keep text in figures and images brief.
  • In text in figures and images, avoid complete sentences and punctuation when possible.
  • Don't embed figure descriptions or captions in the figure or image; put them in text following the figure.
  • Don't create new abbreviations to condense text in figures and images.
  • Use sentence case for text in figures and images, following the guidelines for capitalization for titles and headings.
  • Use numbered callouts in figures to help you write a figure description, but don't use callouts for detailed annotations in the image.
  • Use full trademarked product names in text in figures and images.

High-resolution images

  • To provide a high-resolution image, use the img element's srcset attribute in addition to the standard src attribute.
    • Good: <img src="/assets/images/skateboard.png" srcset="/assets/images/skateboard.png 1x, /assets/images/skateboard_2x.png 2x" width="375" alt="" />
  • When you use the srcset attribute, always still include the src attribute.
  • Set the width attribute to the CSS pixel size used for the page dimensions, and don't state the height explicitly.
  • Set the src attribute to point to the standard-resolution (1x) image, not the 2x version.
  • Use a filename of the form BASENAME_2x.EXTENSION for the double-resolution image.
    • Good: skateboard_2x.png
  • Make the double-resolution image exactly twice the width and height of the standard image, give or take a pixel.
  • Don't scale up an existing 1x image to make the 2x version; if all you have is the 1x version, use it alone.
  • Specify all available image resolutions in the srcset attribute.

Layout of images on a page

  • Don't try to place an image manually, for example with a style attribute; use your site's standard CSS image styles.
  • Don't make your image too small; it's fine for an image to take up the full width of a page.
  • Consider how the image will look when printed out.
  • In general, don't use an image that's wider than the column it appears in.
  • Resize screenshots at full resolution if they take up too much space on the page.
  • Don't link to the figure from within the same page unless it's a very long page and you're linking to it from quite far away on the page.
  • Don't center the image on the page.
  • Don't put an img element inside a p element.
