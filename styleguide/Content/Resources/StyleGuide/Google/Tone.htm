Voice and tone

  • Aim for a voice and tone that's conversational, friendly, and respectful without using slang or being overly colloquial or frivolous.
    • Bad: Dude! This API is totally awesome!
    • Good: This API lets you collect data about what your users like.
  • Aim for a conversational tone rather than a formal one, without writing exactly the way you speak.
    • Bad: The API documented by this page may enable the acquisition of information pertaining to user preferences.
    • Good: This API lets you collect data about what your users like.
  • Don't try to be super-entertaining, but also don't aim for super-dry; the primary purpose is to provide information to someone who may be in a hurry.
  • As much as possible, avoid culturally specific references, and write simply and consistently.

Some things to avoid where possible

  • Avoid buzzwords or technical jargon.
  • Avoid being too cutesy.
  • Avoid figurative language, which includes metaphors and ableist language.
  • Avoid placeholder phrases like please note and at this time.
    • Bad: Please note that completion of the task requires the following prerequisite: executing an automated memory management function.
    • Good: To clean up, call the collectGarbage method.
  • Avoid choppy or long-winded sentences.
  • Avoid starting all sentences with the same phrase (such as You can or To do).
  • Avoid current pop-culture references.
    • Bad: Just like a certain pop star, this call gets your telephone number. The easy way to ask for someone's digits!
    • Good: To get the user's phone number, call user.phoneNumber.get.
  • In general, avoid exclamation points.
    • Bad: Dude! This API is totally awesome!
    • Good: This API lets you collect data about what your users like.
  • Avoid wackiness, zaniness, and goofiness.
    • Bad: Then—BOOM—just garbage-collect, and you're golden.
    • Good: To clean up, call the collectGarbage method.
  • Avoid phrasing that denigrates or insults any group of people.
  • Avoid phrasing in terms of let's do something.
  • Avoid using phrases like simply, It's that simple, It's easy, or quickly in a procedure.
  • Avoid internet slang, or other internet abbreviations such as tl;dr or ymmv.

Some techniques and approaches to consider

  • If a sentence is awkward or confusing when spoken, consider whether you can make it more conversational.
  • Use transitions between sentences, such as Though or This way, to make paragraphs less stilted.
  • Make sure you're communicating useful information in a clear and direct way.

Politeness and use of please

  • Don't use please in a set of instructions.
    • Bad: To view the document, please click View.
    • Good: To view the document, click View.
  • Don't use please when referring readers to other documents.
    • Bad: For more information, please see [link to other document].
    • Good: For more information, see [link to other document].
