About this style guide

This Flare project is the style guide that the Acme Software documentation team checks topics against. The Company folder holds the team's rules. Where a company rule disagrees with the Google developer documentation style guide, the company rule wins.

How to write rules

Only bullets and table rows are rules; paragraphs like this one are context. Keep one rule per bullet. Under a bullet, add a nested list with Bad: and Good: lines so the AI's use of the rule can be tested.

Tables with the headers Avoid, Use, Severity, Why, Example become automatic lint rules. A table with the headers Rule, Setting, Reason turns Google rules off or changes their level.
