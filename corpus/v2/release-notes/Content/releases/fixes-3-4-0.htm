Fixes in 3.4.0

This release fixes the following problems.

Fixes

Core

  • Declarative config now performs proper uniqueness checks against its inputs: previously, it would silently drop entries with conflicting primary/endpoint keys, or accept conflicting unique fields silently (ORB-11199).
  • Fixed a bug that causes POST /config?flatten_errors=1 to throw an exception and return a 500 error under certain circumstances (ORB-10896).
  • Fix a bug when worker consuming dynamic log level setting event and using a wrong reference for notice logging (ORB-10897).
  • Added a User= specification to the systemd unit definition so that can be controlled by systemd again (ORB-11066).
  • Fix a bug that caused sampling rate to be applied to individual spans producing split traces (ORB-11135).
  • Fix a bug that caused the router to fail in traditional_compatible mode when a route with multiple paths and no service was created (ORB-11158).

Admin API

  • Fix an issue where /schemas/plugins/validate endpoint fails to validate valid plugin configuration when the key of custom_fields_by_lua contains dot character(s) (ORB-11091).
  • Fix an issue with the /tags/:tag Admin API returning a JSON object ({}) instead of an array ([]) for empty data sets (ORB-11213).

Plugins

  • Response Transformer: fix an issue that plugin does not transform the response body while upstream returns a Content-Type with +json suffix at subtype (ORB-10656).
  • grpc-gateway: Fixed an issue that empty (all default value) messages can not be unframed correctly (ORB-10836).
  • Validation for queue related parameters has been improved. max_batch_size, max_entries and max_bytes are now integers instead of numbers. initial_retry_delay and max_retry_delay must now be numbers greater than 0.001 (seconds) (ORB-10840).

Status API

  • Remove the database information from the status API when operating in dbless mode or data plane (ORB-10995).
