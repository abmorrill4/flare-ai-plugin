New in 1.1.0

These features and improvements arrived with 1.1.0 on March 27, 2019.

Features

Core

  • can now run without a database, using in-memory storage only. When running in DB-less mode, entities are loaded via a declarative configuration file, specified either through 's configuration file, or uploaded via the Admin API (ORB-4315).
  • Transparent proxying - the service attribute on Routes is now optional; a Route without an assigned Service will proxy transparently (ORB-4286).
  • Support for tags in entities (ORB-4275).
    • Every core entity now adds a tags field
  • New protocols field in the Plugin entity, allowing plugin instances to be set for specific protocols only (http, https, tcp or tls) (ORB-4248).
    • It filters out plugins during execution according to their protocols field
    • It throws an error when trying to associate a Plugin to a Route which is not compatible, protocols-wise, or to a Service with no compatible routes.

Configuration

  • New option in orbit.conf: database=off to start without a database.
  • New option in orbit.conf: declarative_config=orbit.yml to load a YAML file using 's new declarative config format.

CLI

  • Bulk database import using the same declarative configuration format as the in-memory mode, using the new command: orbit config db_import orbit.yml. This command upserts all entities specified in the given orbit.yml file in bulk (ORB-4284).
  • New command: orbit config init to generate a template orbit.yml file to get you started.
  • New command: orbit config parse orbit.yml to verify the syntax of the orbit.yml file before using it.

Admin API

  • New Admin API endpoint: /config to replace the configuration of entities entirely, replacing it with the contents of a new declarative config file (ORB-4308).
    • When using the new database=off configuration option, the Admin API endpoints for entities (such as /routes and /services) are read-only, since the configuration can only be updated via /config
  • Admin API endpoints now support searching by tag (for example, /consumers?tags=example_tag).
    • You can search by multiple tags:
    • /services?tags=serv1,mobile to search for services matching tags serv1 and mobile
    • /services?tags=serv1/serv2 to search for services matching tags serv1 or serv2
  • New Admin API endpoint /tags/ for listing entities by tag: /tags/example_tag.

PDK

  • New PDK function: orbit.client.get_protocol for obtaining the protocol in use during the current request (ORB-4307).

Plugins

  • Support for ACL authenticated groups, so that authentication plugins that use a 3rd party (other than ) to store credentials can benefit from using a central ACL plugin to do authorization for them (ORB-4013).
