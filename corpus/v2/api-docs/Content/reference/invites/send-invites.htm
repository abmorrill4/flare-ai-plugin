Send invitations

POST /invites

Send invitations to specified email addresses.

Changes: In 6.0 (feature level 126), the invite_expires_in_days parameter was removed and replaced by invite_expires_in_minutes.

In 5.0 (feature level 117), added support for passing null as the invite_expires_in_days parameter to request an invitation that never expires.

In 5.0 (feature level 96), the invite_expires_in_days parameter was added which specified the number of days before the invitation would expire.

This endpoint is part of version of the REST API.

Usage examples

Python

# Send invitations.
request = {
    "invitee_emails": "example@example.com, logan@example.com",
    "invite_expires_in_minutes": 60 * 24 * 10,  # 10 days
    "invite_as": 400,
    "stream_ids": stream_ids,
}
result = client.call_endpoint(url="/invites", method="POST", request=request)

curl

# Send invitations
curl -sS -X POST https://chat.example.com/api/v1/invites \
    -u EMAIL_ADDRESS:API_KEY \
    --data-urlencode invitee_emails=example@example.com,\ logan@example.com \
    --data-urlencode 'stream_ids=[1, 10]'

Parameters

Parameter Location Type Required Description
invitee_emails body string Yes The string containing the email addresses, separated by commas or newlines, that will be sent an invitation.
invite_expires_in_minutes body integer No The number of minutes before the invitation will expire. If null, the invitation will never expire. If unspecified, the server will use a default value (based on the INVITATION_LINK_VALIDITY_MINUTES server setting, which defaults to 14400, i.e. 10 days) for when the invitation will expire.
invite_as body integer No The organization-level role of the user that is created when the invitation is accepted. Possible values are:
stream_ids body array of integers Yes A list containing the IDs of the channels that the newly created user will be automatically subscribed to if the invitation is accepted, in addition to any default channels that the new user may be subscribed to based on the include_realm_default_subscriptions parameter.
group_ids body array of integers No A list containing the IDs of the user groups that the newly created user will be automatically added to if the invitation is accepted. If the list is empty, then the new user will not be added to any user groups. The acting user must have permission to add users to the groups listed in this request.
include_realm_default_subscriptions body boolean No Boolean indicating whether the newly created user should be subscribed to the default channels for the organization.
notify_referrer_on_join body boolean No A boolean indicating whether the referrer would like to receive a direct message from notification bot when a user account is created using this invitation.
welcome_message_custom_text body string No Custom message text, in Markdown format, to be sent by the Onboarding Bot to new users that join the organization via this invitation.

Parameter details

invite_expires_in_minutes

Changes: New in 6.0 (feature level 126). Previously, there was an invite_expires_in_days parameter, which specified the duration in days instead of minutes.

invite_as

Possible values: 100, 200, 300, 400, 600.

  • 100 = Organization owner
  • 200 = Organization administrator
  • 300 = Organization moderator
  • 400 = Member
  • 600 = Guest

Users can only create invitation links for roles with equal or stricter restrictions as their own. For example, a moderator cannot invite someone to be an owner or administrator, but they can invite them to be a moderator or member.

Changes: In 4.0 (feature level 61), added support for inviting users as moderators.

stream_ids

Requested channels must either be default channels for the organization, or ones the acting user has permission in order to add subscribers to.

This list must be empty if the current user has the unlikely configuration of being able to send invitations while lacking permission to subscribe other users to channels.

Changes: Prior to 10.0 (feature level 342), default channels that the acting user did not directly have permission to add subscribers to would be rejected.

Before 7.0 (feature level 180), specifying stream_ids as an empty list resulted in an error.

group_ids

Changes: New in 10.0 (feature level 322). Add a short label, e.g. the purpose of the item.

include_realm_default_subscriptions

Note that this parameter can be true even if the user creating the invitation does not generally have permission to subscribe other users to channels.

Changes: New in 9.0 (feature level 261). Previous versions of behaved as though this parameter was always false; clients needed to include the organization's default channels in the stream_ids parameter for a newly created user to be automatically subscribed to them.

notify_referrer_on_join

Changes: New in 9.0 (feature level 267). Previously, referrers always received such direct messages.

Response

Success.

Errors

HTTP 400

Bad request.
