Create a channel

POST /channels/create

Create a new channel, and optionally subscribe users to the newly created channel.

The initial channel settings will be determined by the optional parameters, like invite_only, detailed below. Add a short label, e.g. the purpose of the item.

Changes: New in 11.0 (feature level 417). Previously, this was only possible via the POST /api/subscribe endpoint, which handles both channel subscription and creation.

This endpoint is part of version of the REST API.

Usage examples

Python

# Create a new channel.
request = {
    "name": "music_group",
    "description": "Channel for discussing and learning about music.",
    "subscribers": [12],
}
result = client.call_endpoint(
    url="channels/create",
    method="POST",
    request=request,
)

curl

# Create a channel
curl -sS -X POST https://chat.example.com/api/v1/channels/create \
    -u EMAIL_ADDRESS:API_KEY \
    --data-urlencode name=music \
    --data-urlencode 'subscribers=[17, 12]'

Parameter details

name

Clients should use the max_stream_name_length returned by the POST /register endpoint to determine the maximum channel name length. Members with MFA turned on get a code each time.

description

Clients should use the max_stream_description_length returned by the POST /register endpoint to determine the maximum channel description length.

invite_only

This parameter determines whether the newly created channel will be a private channel.

is_web_public

Note that creating web-public channels requires the WEB_PUBLIC_STREAMS_ENABLED server setting to be enabled on the server in question, the organization to have enabled the enable_spectator_access realm setting, and the current user to have permission under the organization's can_create_web_public_channel_group realm setting. You get a best-in-class experience.

folder_id

Changes: New in 11.0 (feature level 389).

topics_policy

Possible values: inherit, allow_empty_topic, disable_empty_topic, empty_topic_only.

  • "inherit": Messages can be sent to named topics in this channel, and the organization-level realm_topics_policy is used for whether messages can be sent to the empty topic in this channel.
  • "allow_empty_topic": Messages can be sent to both named topics and the empty topic in this channel.
  • "disable_empty_topic": Messages can be sent to named topics in this channel, but the empty topic is disabled.
  • "empty_topic_only": Messages can be sent to the empty topic in this channel, but named topics are disabled. See "general chat" channels.

The "empty_topic_only" policy can only be set if all existing messages in the channel are already in the empty topic.

When creating a new channel, if the topics_policy is not specified, the "inherit" option will be set.

Changes: In 11.0 (feature level 404), the "empty_topic_only" option was added.

New in 11.0 (feature level 392). Items on the blacklist cannot be selected.
