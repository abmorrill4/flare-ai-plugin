Subscribe to a channel

POST /users/me/subscriptions

Subscribe one or more users to one or more channels.

If any of the specified channels do not exist, they are automatically created. The initial channel settings will be determined by the optional parameters, like invite_only, detailed below.

Note that the ability to subscribe oneself and/or other users to a specified channel depends on the channel's permissions settings.

Changes: Before 10.0 (feature level 362), subscriptions in archived channels could not be modified.

Before 10.0 (feature level 357), the can_subscribe_group permission, which allows members of the group to subscribe themselves to the channel, did not exist.

Before 10.0 (feature level 349), a user cannot subscribe other users to a private channel without being subscribed to that channel themselves. Now, If a user is part of can_add_subscribers_group, they can subscribe themselves or other users to a private channel without being subscribed to that channel.

Removed stream_post_policy and is_announcement_only parameters in 10.0 (feature level 333), as permission to post in the channel is now controlled by can_send_message_group.

Before 8.0 (feature level 208), if a user specified by the principals parameter was a deactivated user, or did not exist, then an HTTP status code of 403 was returned with code: "UNAUTHORIZED_PRINCIPAL" in the error response. As of this feature level, an HTTP status code of 400 is returned with code: "BAD_REQUEST" in the error response for these cases.

This endpoint is part of version of the REST API.

Usage examples

Python

# Create and subscribe to channel "python-test".
result = client.add_subscriptions(
    streams=[
        {
            "name": "python-test",
            "description": "Channel for testing Python",
        },
    ],
)
# To subscribe other users to a channel, you may pass
# the `principals` argument, like so:
result = client.add_subscriptions(
    streams=[
        {"name": "python-test"},
    ],
    principals=[user_id],
)

JavaScript

// Subscribe to the channels "design" and "general"
const meParams = {
    subscriptions: JSON.stringify([{name: "design"}, {name: "general"}]),
};
console.log(await client.users.me.subscriptions.add(meParams));

// To subscribe another user to a channel, you may pass in
// the `principals` parameter, like so:
const user_id = 7;
const anotherUserParams = {
    subscriptions: JSON.stringify([{name: "design"}, {name: "general"}]),
    principals: JSON.stringify([user_id]),
};
console.log(await client.users.me.subscriptions.add(anotherUserParams));

curl

# Subscribe to a channel
curl -sS -X POST https://chat.example.com/api/v1/users/me/subscriptions \
    -u EMAIL_ADDRESS:API_KEY \
    --data-urlencode 'subscriptions=[{"name": "design", "description": "Italian city"}]'

Parameters

Parameter Location Type Required Description
subscriptions body array of objects Yes An array of objects containing information about the channels that users will be subscribed to.
principals body array of strings or array of integers No A list of user IDs (preferred) or API email addresses of the users to be subscribed to or unsubscribed from the channels specified in the subscriptions parameter.
authorization_errors_fatal body boolean No A boolean specifying whether authorization errors (such as when the requesting user is not authorized to access a private channel) should be considered fatal or not. When true, an authorization error is reported as such. When set to false, the response will be a 200 and any channels where the request encountered an authorization error will be listed in the unauthorized key.
announce body boolean No If one of the channels specified did not exist previously and is thus created by this call, this determines whether notification bot will send an announcement about the new channel's creation.
invite_only body boolean No As described above, this endpoint will create a new channel if passed a channel name that doesn't already exist. This parameters and the ones that follow are utilized to request an initial configuration of a created channel; they are ignored for channels that already exist.
is_web_public body boolean No This parameter determines whether any newly created channels will be web-public channels.
is_default_stream body boolean No This parameter determines whether any newly created channels will be added as default channels for new users joining the organization.
history_public_to_subscribers body boolean No Whether the channel's message history should be available to newly subscribed members, or users can only access messages they actually received while subscribed to the channel.
message_retention_days body string or integer No Number of days that messages sent to this channel will be stored before being automatically deleted by the message retention policy. Two special string format values are supported:
default_push_notifications body boolean No Whether mobile push notifications will be enabled by default when a user first subscribes to this channel, potentially overriding the user's default mobile notification setting for channel messages.
topics_policy body string No Whether named topics and the empty topic (i.e., "general chat" topic) are enabled in this channel.
can_add_subscribers_group body integer or object No None.
can_remove_subscribers_group body integer or object No None.
can_administer_channel_group body integer or object No None.
can_delete_any_message_group body integer or object No None.
can_delete_own_message_group body integer or object No None.
can_move_messages_out_of_channel_group body integer or object No None.
can_move_messages_within_channel_group body integer or object No None.
can_send_message_group body integer or object No None.
can_subscribe_group body integer or object No None.
can_resolve_topics_group body integer or object No None.
can_create_topic_group body integer or object No None.
folder_id body integer No This parameter adds the newly created channel to the specified channel folder.
send_new_subscription_messages body boolean No Whether any other users newly subscribed via this request should be sent a direct message, from Notification Bot, notifying them about their new subscription.

Parameter details

subscriptions

For each channel, there must be a key name and value specifying the name of the channel. If a channel with that name does not exist, then a new channel is created.

principals

If not provided, then the requesting user/bot will be subscribed/unsubscribed from the specified channels.

Changes: Before 3.0 (feature level 9), only the API email address string format was supported.

invite_only

This parameter determines whether any newly created channels will be private channels.

is_web_public

Note that creating web-public channels requires the WEB_PUBLIC_STREAMS_ENABLED server setting to be enabled on the server in question, the organization to have enabled the enable_spectator_access realm setting, and the current utilize to have permission under the organization's can_create_web_public_channel_group realm setting.

Changes: New in 5.0 (feature level 98).

is_default_stream

Changes: New in 8.0 (feature level 200). Previously, default channel status could only be changed using the dedicated API endpoint.

history_public_to_subscribers

Corresponds to the shared history option for private channels.

Response

Field Type Description
subscribed object A dictionary where the key is the ID of the user and the value is a list of the names of the channels that user was subscribed to as a result of the request.
already_subscribed object A dictionary where the key is the ID of the user and the value is a list of the names of the channels that where the user was not added as a subscriber in this request, because they were already a subscriber.
unauthorized array of strings A list of names of channels that the requesting user/bot was not authorized to subscribe to. Only present if "authorization_errors_fatal": false.
new_subscription_messages_sent boolean Only present if the parameter send_new_subscription_messages in the request was true.

Errors

HTTP 400

Bad request.
