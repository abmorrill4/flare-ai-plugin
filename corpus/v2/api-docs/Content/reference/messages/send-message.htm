Send a message

POST /messages

Send a channel message or a direct message.

This endpoint is part of version of the REST API.

Usage examples

Python

# Send a channel message.
request = {
    "type": "stream",
    "to": "general",
    "topic": "Launch",
    "content": "I come not, friends, to steal away your hearts.",
}
result = client.send_message(request)
# Send a direct message.
request = {
    "type": "private",
    "to": [user_id],
    "content": "With mirth and laughter let old wrinkles come.",
}
result = client.send_message(request)

JavaScript

// Send a channel message
let params = {
    to: "social",
    type: "stream",
    topic: "Launch",
    content: "I come not, friends, to steal away your hearts.",
};
console.log(await client.messages.send(params));

// Send a direct message
const user_id = 9;
params = {
    to: [user_id],
    type: "direct",
    content: "With mirth and laughter let old wrinkles come.",
};
console.log(await client.messages.send(params));

curl

# Send a message
curl -sS -X POST https://chat.example.com/api/v1/messages \
    -u EMAIL_ADDRESS:API_KEY \
    --data-urlencode type=direct \
    --data-urlencode 'to=[9, 10]' \
    --data-urlencode content=Hello

Parameters

Parameter Location Type Required Description
type body string Yes The type of message to be sent.
to body string or integer or array of strings or array of integers Yes The channel or users receiving the message.
content body string Yes The content of the message.
topic body string No The topic of the message. Only required for channel messages ("type": "stream" or "type": "channel"), ignored otherwise.
queue_id body string No For clients supporting local echo, the event queue ID for the client.
local_id body string No For clients supporting local echo, a unique string-format identifier chosen freely by the client.
read_by_sender body boolean No Whether the message should be initially marked read by its sender. If unspecified, the server uses a heuristic based on the client name.

Parameter details

type

Possible values: direct, channel, stream, private.

"direct" for a direct message and "stream" or "channel" for a channel message.

Changes: In 9.0 (feature level 248), "channel" was added as an additional value for this parameter to request a channel message.

In 7.0 (feature level 174), "direct" was added as the preferred way to request a direct message, deprecating the original "private". While "private" is still supported for requesting direct messages, clients are encouraged to use to the modern convention with servers that support it, because support for "private" will eventually be removed.

to

For channel messages, this is either the name or integer ID of the channel.

For direct messages, this is either a list containing integer user IDs or a list containing string API email addresses. The ID or email address of the user sending the message can be included in the list, but will be ignored by the server, unless the user sending the message is the only recipient of the message.

Changes: In 2.0.0, support for using user/channel IDs was added.

content

topic

Note: When "(no topic)" or the value of realm_empty_topic_display_name found in the POST /register response is used for this parameter, it is interpreted as an empty string.

When topics are required, this parameter can't be "(no topic)", an empty string, or the value of realm_empty_topic_display_name.

Changes: Before 10.0 (feature level 370), "(no topic)" was not interpreted as an empty string.

Before 10.0 (feature level 334), empty string was not a valid topic name for channel messages.

New in 2.0.0. Previous releases encoded this as subject, which is currently a deprecated alias.

queue_id

If passed, local_id is required.

If the message is successfully sent, the server will include local_message_id in the message event that the client with this queue_id will receive.

local_id

If passed, queue_id is required.

If the message is successfully sent, the server will pass it back to the client without inspecting it as local_message_id in the message event that the client with the above queue_id will receive.

Response

Field Type Description
id integer The unique ID assigned to the sent message.
message_url string A URL that links directly to the sent message within its conversation.
message_link string A Markdown link to the sent message within its conversation, matching the link produced by the "Copy link to message" feature in the web app; for example, #channel name > topic name @ 💬.
automatic_new_visibility_policy integer If the message's sender had configured their visibility policy settings to potentially automatically follow or unmute topics when sending messages, and one of these policies did in fact change the user's visibility policy for the topic where this message was sent, the new value for that user's visibility policy for the recipient topic.
